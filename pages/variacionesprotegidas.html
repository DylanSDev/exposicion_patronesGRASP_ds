El Patrón de Variaciones Protegidas

Una solución GRASP para aislar el sistema de cambios e inestabilidades.

😕 El Problema

En un sistema de software siempre existen puntos de inestabilidad: requisitos que cambian, APIs externas, reglas de negocio que se actualizan, etc. Un mal diseño provoca que cada cambio en una parte impacte en múltiples clases, generando alto acoplamiento y un elevado costo de mantenimiento. La pregunta clave es: ¿cómo diseñar para que estas variaciones no afecten al resto del sistema?

Analogía: Los Enchufes Eléctricos

Instalación Eléctrica Doméstica
▼
Problema: Si cada electrodoméstico necesitara un enchufe diferente.
Consecuencia: Habría que rehacer la instalación eléctrica cada vez que se compra un nuevo aparato.

¡Un pequeño cambio (nuevo aparato) generaría un gran impacto en toda la casa (sistema)!

✨ La Solución

El patrón Variaciones Protegidas propone identificar los puntos de posible cambio y encapsularlos detrás de una interfaz estable. De esta manera, los clientes del sistema dependen de esta interfaz fija, y no de las implementaciones concretas que pueden variar. Esto protege al sistema del impacto de los cambios y facilita su extensión.

La instalación eléctrica (la interfaz estable) no cambia. Solo cambian los adaptadores de cada dispositivo (las implementaciones variables).

⚙️ Tipos o Variantes

El patrón no tiene una clasificación formal, pero se manifiesta a través de distintos enfoques de diseño:

  • Protección mediante Interfaces (Polimorfismo): Se define una interfaz y varias implementaciones posibles. Es ideal cuando se esperan múltiples variaciones de comportamiento.
  • Protección mediante Indirección (Intermediarios): Se introduce un objeto intermediario (Adaptador, Proxy, Fachada) para desacoplar dependencias externas o APIs inestables.
  • Protección mediante Encapsulación de Datos: Se ocultan las estructuras de datos internas, exponiendo solo las operaciones necesarias para proteger a los clientes de cambios en la representación interna.

🛠️ Ejemplos

Ejemplo Cotidiano: Caja Fuerte

El mecanismo interno de una caja fuerte puede variar (electrónico, mecánico, biométrico), pero la interfaz estable no cambia: el usuario siempre interactúa con un teclado o un lector para introducir una clave y abrirla.

Ejemplo en Software: Sistema de Pagos

En un e-commerce, se deben soportar distintos métodos de pago (tarjeta, PayPal, cripto). Si el sistema se acopla directamente a cada API de pago, cualquier cambio en una de ellas rompería el código. La solución es crear una interfaz estable IMetodoPago que todas las formas de pago implementarán.

Java
// 1. Interfaz Estable
public interface IMetodoPago {
    boolean procesarPago(double monto);
}

// 2. Implementación Concreta: Tarjeta
public class PagoTarjeta implements IMetodoPago {
    @Override
    public boolean procesarPago(double monto) {
        System.out.println("Procesando pago con tarjeta por $" + monto);
        return true;
    }
}

// 3. Implementación Concreta: PayPal
public class PagoPayPal implements IMetodoPago {
    @Override
    public boolean procesarPago(double monto) {
        System.out.println("Procesando pago con PayPal por $" + monto);
        return true;
    }
}

// 4. Implementación Concreta: Criptomonedas
public class PagoCripto implements IMetodoPago {
    @Override
    public boolean procesarPago(double monto) {
        System.out.println("Procesando pago en criptomonedas por $" + monto);
        return true;
    }
}

⚖️ Pros y Contras

Beneficios

  • Se pueden añadir nuevas variaciones (ej. nuevos métodos de pago) sin modificar el código cliente.
  • Reduce el acoplamiento entre los componentes del sistema.
  • Disminuye el impacto y el costo de los cambios a largo plazo.
  • Aumenta la flexibilidad y la reutilización del código.

Desventajas

  • Puede generar sobre-ingeniería si se aplican capas de protección innecesarias.
  • Existe el riesgo de protegerse contra variaciones que nunca ocurrirán.
  • Puede añadir una mayor complejidad inicial, especialmente en sistemas pequeños.

Principio Clave de Variaciones Protegidas:

Identifica los puntos de inestabilidad y encapsúlalos detrás de una interfaz estable para proteger el sistema del impacto de los cambios.
