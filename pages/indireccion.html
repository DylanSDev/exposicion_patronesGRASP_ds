El Patrón de Indirección

Una solución GRASP para un software desacoplado y reutilizable.

😕 El Problema: Alto Acoplamiento

Cuando dos o más componentes de un sistema están fuertemente conectados, cualquier cambio en uno de ellos obliga a modificar a los otros. Esto genera un software frágil, difícil de mantener, probar y reutilizar. A este problema se le conoce como "alto acoplamiento".

Analogía: Comprar en el Extranjero

Comprador en Argentina
▼
SI quiere comprar en Japón...
Debe conseguir Yenes, entender leyes bancarias japonesas, hacer transferencias internacionales y coordinar zonas horarias.

¡El comprador está "fuertemente acoplado" a los procesos y requisitos de la tienda japonesa!

✨ La Solución: El Intermediario

El patrón Indirección resuelve el problema del alto acoplamiento asignando la responsabilidad de la comunicación entre dos componentes a un objeto intermediario. Este intermediario desacopla a los componentes originales, que ya no se conocen directamente entre sí.

Analogía: Usando una Tarjeta de Crédito

Comprador usa Tarjeta de Crédito (Visa)
▼
Comprador
Paga a Visa en Pesos Argentinos.
Visa (Intermediario)
Convierte la moneda y paga a la tienda.
Tienda en Japón
Recibe el pago de Visa en Yenes.

¡La tarjeta de crédito (el objeto de indirección) ha desacoplado al comprador del vendedor!

⚙️ Tipos o Variantes

El patrón Indirección es un principio fundamental que se manifiesta a través de otros patrones de diseño más específicos. No tiene "variantes" formales, sino implementaciones concretas. Aquí se detallan dos de las más comunes:

Fachada (Facade)

El patrón Fachada proporciona una interfaz unificada y simplificada a un conjunto de interfaces en un subsistema. Define un punto de entrada de alto nivel que hace que el subsistema sea más fácil de usar.

Adaptador (Adapter)

El patrón Adaptador permite que interfaces incompatibles trabajen juntas. Actúa como un traductor entre dos clases, convirtiendo la interfaz de una clase en otra que el cliente espera.

🛠️ Ejemplos

Ejemplo Cotidiano: El Enchufe Eléctrico

No conectas tu notebook directamente a los cables de alta tensión de la red eléctrica. El enchufe, la toma de corriente y el transformador de tu cargador actúan como capas de indirección. Estos intermediarios adaptan el voltaje, proveen una interfaz estándar y te desacoplan de la complejidad y el peligro de la red eléctrica.

Ejemplo con Código: Terminal de Venta

Un objeto Venta necesita el precio de un producto. En lugar de que Venta consulte directamente la base de datos (alto acoplamiento), le pide la información a un objeto CatalogoProductos. Este catálogo es el intermediario.

Java
public class Venta {
    private CatalogoProductos catalogo;

    public Venta(CatalogoProductos catalogo) {
        this.catalogo = catalogo;
    }

    public void agregarItem(int idProducto, int cantidad) {
        // Venta no sabe cómo se obtiene el producto.
        // Se lo pide al intermediario (catalogo).
        EspecificacionProducto producto = catalogo.getEspecificacion(idProducto);
        
        // ... usar producto para calcular el total
    }
}

Diagrama UML de la Solución

Venta
▼ se comunica con
CatalogoProductos (Intermediario)
▼ obtiene datos de
EspecificacionProducto (Datos)

La clase Venta solo se comunica con CatalogoProductos, que actúa como intermediario. Así, Venta y EspecificacionProducto están desacoplados.

⚖️ Pros y Contras

Beneficios

  • Menor Acoplamiento: Los componentes se vuelven más independientes. Los cambios en uno no afectan necesariamente a los demás.
  • Mayor Reutilización: Al estar desacoplados, los componentes individuales son más fáciles de usar en diferentes partes del sistema o en otros proyectos.
  • Facilita las Pruebas Unitarias: Permite aislar componentes para probarlos de forma independiente, reemplazando al intermediario por un "doble de prueba".

Desventajas

  • Mayor Complejidad: Se introduce un objeto adicional (el intermediario), lo que puede aumentar la complejidad del diseño si se usa en exceso.
  • Posible Impacto en el Rendimiento: Añadir una capa de indirección puede introducir una pequeña sobrecarga en el rendimiento debido a la delegación de llamadas.

Principio Clave de la Indirección:

Asigna la responsabilidad a un objeto intermedio para desacoplar componentes y así reducir el impacto de los cambios.
